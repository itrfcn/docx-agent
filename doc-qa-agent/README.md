# 企业文档问答助手

一个轻量的**通用企业文档问答知识库 Agent**：把企业内部文档上传入库，基于 LangChain 原生 ReAct Agent 自主检索并作答，答案附带可点击回溯的引用来源。

不依赖任何外部联网检索，也不限定行业，适合快速搭建一个"只回答自家资料"的内部问答工具。

## 核心特性

| 特性         | 说明                                                |
| ---------- | ------------------------------------------------- |
| 文档入库       | 支持 PDF / DOCX / DOC / TXT / XLSX / XLS 及 JPG / PNG 等图片，可一次多选上传 |
| 扫描件 OCR    | 扫描版 PDF 无文本层的页自动 OCR；图片直接 OCR，全程本地离线运行          |
| 本地向量化      | 使用 `BAAI/bge-small-zh-v1.5` 本地 Embedding，文档内容不出内网 |
| 持久化知识库     | Chroma 本地持久化，重启程序数据不丢失                            |
| Agent 自主检索 | LangChain 原生 ReAct Agent，自主判断是否需要检索，只注册 1 个检索工具   |
| 引用可回溯      | 回答标注 `【来源：文件名】`，并支持在浏览器中查看原文、自动定位到页码/行、下载原文件      |
| 防编造        | 多轮检索仍不足时明确回复"知识库中暂未检索到相关资料"，不臆测参数、流程或制度条款         |
| 多轮对话       | 结合历史上下文理解追问，支持连续问答                                |
| 表格友好       | Excel 按"一行一个切片"入库，自动识别表头、填充合并单元格、过滤年度统计表          |
| 管理隔离       | 上传、删除、清空需要管理员口令；普通员工只能查看文档列表与问答                   |
| 会话级 API 配置 | 管理员可在侧边栏临时切换 API 地址/密钥/模型，也可写回 `.env` 作为全局默认      |

## 适用场景

- 管理制度、流程规范（考勤、差旅、报销、奖惩、信息安全等）
- 产品资料、技术文档、操作手册
- FAQ、培训材料、新人指南
- 其他需要集中检索问答的内部文件

## 技术栈

| 组件        | 选型                                                        | 说明                      |
| --------- | --------------------------------------------------------- | ----------------------- |
| Web 界面    | Streamlit                                                 | 侧边栏管理 + 主区域聊天           |
| Agent 框架  | LangChain 原生 `create_react_agent` + `AgentExecutor`       | 不使用 LangGraph           |
| 向量库       | Chroma（本地持久化）                                             | cosine 距离空间             |
| Embedding | sentence-transformers `BAAI/bge-small-zh-v1.5`            | 本地 CPU 运行，约 90 MB       |
| 文档解析      | pdfplumber / python-docx / pywin32(COM) / openpyxl / xlrd | 见[支持的文档格式](#支持的文档格式)    |
| OCR       | RapidOCR（onnxruntime）                                     | 本地离线运行，模型随包内置，无需联网            |
| 配置        | python-dotenv                                             | 读取项目根目录 `.env`          |
| LLM       | 通义千问（OpenAI 兼容接口）                                         | 默认 `qwen-plus`，可换任意兼容模型 |

> 依赖版本在 `requirements.txt` 中锁定：LangChain 固定 `0.3.x`（`1.x` 已移除 ReAct 相关接口）；`.xls` 需要 `xlrd>=1.2,<2.0`；OCR 依赖 `rapidocr-onnxruntime`（会带入 onnxruntime 与 opencv），整体安装包会比无 OCR 版本大 100 MB 左右。

## 工作原理

```
上传文件 → 解析文本（扫描页 / 图片自动 OCR）→ 切片 → bge-small-zh 向量化 → Chroma 持久化
                                                        │
用户提问 → ReAct Agent（Thought/Action） → knowledge_search ─┘
                    │
                    ├─ 相似度检索 + 相关性阈值过滤 + 同源条数限制
                    └─ LLM 基于片段作答 → 标注【来源：文件名】→ 前端提供原文预览
```

几个关键设计：

1. **检索固定使用用户原始问题**。LLM 自行扩写关键词会被忽略，避免长 query 带来的向量"维度诅咒"和假阳性来源。
2. **宁可少答，不硬凑**。检索分数低于阈值（默认 `0.45`）的片段直接丢弃；确实没有资料时明确拒答。
3. **实质回答必须有真实检索支撑**。若模型没调用检索就直接给出长答案，或 ReAct 收敛失败，会自动走"直接检索 + 单次 LLM 直答"的降级路径。

## 快速开始

### 1. 环境要求

- Python 3.10+（开发验证环境为 Python 3.12）
- Windows（`.doc` 解析与 Word→PDF 预览依赖本机安装 Microsoft Word；其余功能跨平台可用）
- 首次运行需要能访问模型下载源，或提前准备好本地模型缓存

### 2. 安装依赖

```powershell
cd doc-qa-agent

# 创建并激活虚拟环境
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 安装依赖（国内建议用清华源）
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 3. 配置环境变量

```powershell
copy .env.example .env
```

编辑 `.env`，至少填写：

```ini
OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
OPENAI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
MODEL_NAME=qwen-plus
ADMIN_PASSWORD=你的管理口令
```

### 4. 启动

```powershell
streamlit run app.py
```

默认打开 `http://localhost:8501`。如需指定端口：

```powershell
streamlit run app.py --server.port 8502
```

### 5. 首次运行与模型下载

`utils/__init__.py` 与 `app.py` 默认设置了以下环境变量，用于跳过联网检查、加速启动：

```text
HF_ENDPOINT=https://hf-mirror.com
HF_HUB_OFFLINE=1
TRANSFORMERS_OFFLINE=1
```

**如果本机还没有** **`bge-small-zh-v1.5`** **缓存**，离线模式会导致模型加载失败。二选一：

- 临时去掉离线设置后启动一次，让模型自动下载（走 hf-mirror 镜像）；
- 或先手动下载模型到本地缓存目录，再用 `EMBEDDING_MODEL` 指向本地路径。

```powershell
# 临时方式：在当前终端覆盖为在线模式
$env:HF_HUB_OFFLINE = "0"
$env:TRANSFORMERS_OFFLINE = "0"
streamlit run app.py
```

## 配置说明

所有配置均通过项目根目录 `.env` 读取，修改后重启服务生效（API 三项除外，见下文）。

| 变量                    | 必填 | 默认值                      | 说明                                                                  |
| --------------------- | -- | ------------------------ | ------------------------------------------------------------------- |
| `OPENAI_API_KEY`      | 是  | —                        | LLM API Key                                                         |
| `OPENAI_BASE_URL`     | 是  | —                        | OpenAI 兼容接口地址，如 `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `MODEL_NAME`          | 否  | `qwen-plus`              | 模型名，如 `qwen-turbo` / `qwen-max`                                     |
| `EMBEDDING_MODEL`     | 否  | `BAAI/bge-small-zh-v1.5` | 本地 Embedding 模型名或本地路径                                               |
| `CHROMA_PERSIST_DIR`  | 否  | `./data/chroma`          | 向量库持久化目录                                                            |
| `DOCS_DIR`            | 否  | `./data/docs`            | 上传文件落盘目录（预览/下载依赖此目录）                                                |
| `CHUNK_SIZE`          | 否  | `400`                    | 文本切片长度（按中文字符）                                                       |
| `CHUNK_OVERLAP`       | 否  | `64`                     | 切片重叠长度                                                              |
| `RETRIEVER_TOP_K`     | 否  | `4`                      | 每次检索返回的片段数上限                                                        |
| `RELEVANCE_THRESHOLD` | 否  | `0.45`                   | 相关性阈值（0\~1），低于该分数的片段不返回                                             |
| `OCR_MIN_TEXT_CHARS`  | 否  | `20`                     | PDF 页面文本少于该字符数时视为扫描页并 OCR；设为 `0` 可关闭自动 OCR                          |
| `OCR_DPI`             | 否  | `200`                    | 扫描页渲染 DPI；调高更清晰但明显更慢                                                |
| `ADMIN_PASSWORD`      | 否  | 空                        | 管理口令；留空则锁定上传/删除/清空功能                                                |
| `IMPORT_DOCS_DIR`     | 否  | `./data/docs`            | **仅批量导入脚本使用**，扫描目录                                                  |

> `.env` 含密钥，请勿提交到代码仓库。

## 使用指南

### 管理员登录

- 在侧边栏输入 `ADMIN_PASSWORD` 登录后，才会出现上传、删除、清空入口。
- 登录状态通过 URL 中的派生令牌保持，刷新页面不会掉线；修改口令后旧令牌自动失效。
- 未配置口令时，管理功能锁定，普通用户只能查看文档列表和使用问答。

### 上传文档

1. 管理员登录后，在侧边栏「📤 上传文档」中选择文件（支持多选）。
2. 点击「✅ 入库所选文件」，界面会显示每个文件的入库结果与切片数。
3. 同名文件再次上传会**覆盖更新**：先删除旧切片再写入新切片，不会产生重复内容。
4. 原始文件会复制到 `data/docs/`，用于后续预览和下载。
5. 扫描版 PDF 和图片会自动 OCR，界面按页显示解析进度；页数多时请耐心等待，期间不要重复点击。若确认不需要扫描件识别，可在 `.env` 中设置 `OCR_MIN_TEXT_CHARS=0`。

### 问答与引用

- 在底部输入框提问，例如"差旅报销的审批流程是什么？"。
- 回答末尾会标注 `【来源：文件名】`，并附固定提示语"本工具仅作辅助参考……"。
- 回答下方列出「📎 引用来源」，点击即可：
  - 浏览器内预览引用位置附近的原文（命中片段高亮）；
  - 在新标签页打开 PDF（Word 文档会通过本机 Word 转成 PDF，并跳到对应页码）；
  - 在新标签页查看网页版全文（自动滚动到引用行）；
  - 下载原始文件。

> 预览依赖 `.streamlit/config.toml` 中的 `enableStaticServing = true`，且预览地址形如 `/app/static/preview/...`；若部署在反向代理下，请确保该前缀被正确转发。

### 文档维护

- **删除单个文档**：管理员在「📂 已入库文档」列表点击 🗑，二次确认后删除该文档的全部切片，不影响其它文档。
- **清空知识库**：「🗑️ 危险操作 → 清空整个知识库」，需勾选确认后执行，操作不可恢复。
- 清空采用"删除并重建 collection"的方式，规避 Windows 下文件被占用导致的 `WinError 32`；少量残留缓存文件会在进程退出后自然释放。

### API 设置

管理员（或未配置口令的本地模式）可在侧边栏「⚙️ API 设置」中：

- 查看当前生效的模型、地址、脱敏后的密钥；
- **测试连接**：快速校验地址/密钥/模型名是否可用（可区分 401、404、超时）；
- **应用到本会话**：仅当前会话生效，适合临时切换；
- **保存为全局默认**：写回 `.env` 并同步运行时配置，对所有人生效（需勾选确认）。

## 检索与回答机制

### 入库与切片

- **文本类文档**（PDF / DOCX / DOC / TXT）：按 `CHUNK_SIZE=400`、`CHUNK_OVERLAP=64` 递归切分，分隔符优先段落、换行、中文句号/问号/分号等。
- **PDF**：使用分页符保留页码边界，切片 metadata 记录 `page`。页面文本少于 `OCR_MIN_TEXT_CHARS` 时，自动把该页渲染成图片交给 RapidOCR 识别；有文本层的页面直接提取，不触发 OCR。
- **图片**（JPG / PNG / BMP / TIFF / WEBP）：整张图 OCR 后按普通文本切片，图片按 `line` 定位。
- **其它文本**：记录 `line`（起始行号）与 `snippet`（用于 Word 定位的原文片段）。
- **Excel**：
  - 一行一个切片，不做字符级切分，避免整行语义被切断；
  - 自动识别多级表头、补充空列名、填充合并单元格；
  - 过滤年度统计/计划类工作表，减少噪声；
  - 单行过长时按列分组拆分，每块仍保留表格名与行主键。

### 检索策略

| 机制          | 行为                                      |
| ----------- | --------------------------------------- |
| 查询指令前缀      | 查询向量附加 bge 官方检索指令，文档向量不加，提升中文召回         |
| 距离空间        | cosine，相关性分数 = `1 - 余弦距离`               |
| 候选池         | 取 `top_k × 4`，避免单个大文件占满候选               |
| 阈值过滤        | 低于 `RELEVANCE_THRESHOLD` 的片段直接丢弃        |
| 同源限制        | 普通文档每个文件最多 3 片，Excel 最多 5 片，保证来源多样性     |
| Excel 词面补召回 | 对稀有实体词（国家/城市/职级等）按 IDF 加权加分，解决向量区分度低的问题 |
| 关键词重叠兜底     | 长查询命中片段必须与问题有词面交集，过滤 LLM 扩写带来的假阳性       |
| 异常兜底        | HNSW 索引异常时自动降级为普通相似度检索，再降级为全量余弦暴力检索     |

### Agent 行为

- 仅注册 1 个工具：`knowledge_search`，无联网、无代码执行。
- 单轮问答最多真正检索 2 次；重复检索会返回相同结果，并提示模型直接作答，避免空转。
- `max_iterations=10`、`max_execution_time=120` 秒，防止死循环和长时间卡住。
- 宽松 ReAct 解析器：模型漏写 `Final Answer:` 但内容完整时直接采纳，减少一次无谓的 LLM 调用。
- 降级直答：ReAct 解析失败、超时、迭代耗尽，或回答缺乏检索依据时，自动执行"检索 + 单次直答"，并补齐来源与提示语。

### 回答规则

系统 Prompt 位于 `prompts/system_prompt.py`，可直接修改。默认规则：

1. 业务问题必须先检索再回答；
2. 检索不足时明确回复"知识库中暂未检索到与该问题相关的资料"，禁止编造；
3. 每个结论标注来源文档名；
4. 回答末尾附加固定提醒：⚠️ 本工具仅作辅助参考，请以正式文件与责任人判断为准。

## 支持的文档格式

| 格式      | 解析方式              | 说明                                              |
| ------- | ----------------- | ----------------------------------------------- |
| `.pdf`  | pdfplumber + RapidOCR | 有文本层直接提取；无文本层的扫描页自动 OCR；加密/损坏会给出友好提示            |
| `.docx` | python-docx       | 同时提取正文段落与表格文本                                   |
| `.doc`  | Word COM（pywin32） | 需要 Windows + 本机安装 Microsoft Word；否则请另存为 `.docx` |
| `.txt`  | 内置                | 自动尝试 UTF-8，失败回退 GBK                             |
| `.xlsx` | openpyxl          | 行级切片，支持合并单元格                                    |
| `.xls`  | xlrd 1.x          | 行级切片；解析失败建议另存为 `.xlsx`                          |
| `.jpg` / `.jpeg` / `.png` / `.bmp` / `.tif` / `.tiff` / `.webp` | RapidOCR | 整张图 OCR；无 PDF 版式预览，引用时展示识别文本     |

单文件解析失败不会影响其它文件，界面会显示具体失败原因。

## 数据存储

| 路径                   | 内容                                       | 是否可删除                            |
| -------------------- | ---------------------------------------- | -------------------------------- |
| `data/chroma/`       | Chroma 向量库（collection：`enterprise_docs`） | 可通过"清空知识库"安全清空                   |
| `data/docs/`         | 上传的原始文件                                  | 删除后对应文档将无法预览/下载                  |
| `data/manifest.json` | 文档内容哈希、切片数、更新时间                          | 删除后批量导入会视为新文件重建                  |
| `static/preview/`    | 生成的 PDF / HTML 预览缓存                      | 可随时删除，按 24 小时/200 个文件/50 MB 自动清理 |

备份知识库时，至少备份 `data/chroma/`、`data/docs/`、`data/manifest.json`。

## 批量导入（可选）

企业环境不方便使用网页上传时，可把文档放进 `data/docs/`（支持子目录），执行：

```powershell
python import_docs.py
```

行为说明：

- 递归扫描 `data/docs` 下所有受支持格式（含图片），跳过 Word 临时文件 `~$xxx`；
- 扫描件与图片自动 OCR，每 10 页打印一次解析进度；
- 已入库且内容哈希未变化的文件自动跳过；
- 内容变化的文件先删旧切片再重建；
- 单个文件失败不影响其余文件，结束时输出汇总与失败明细；
- 子目录中的文件以相对路径作为文档名（如 `制度/考勤.docx`）。

可通过环境变量指定其它目录：

```powershell
$env:IMPORT_DOCS_DIR = "D:\企业文档"
python import_docs.py
```

导入后刷新页面即可看到新文档；若列表未更新，重启 Streamlit 服务（数据已持久化，不会丢失）。

## 常见问题

**Q：启动时报模型加载失败 / 一直联网超时？**
A：默认开启了 HF 离线模式。若本地没有模型缓存，请参考[首次运行与模型下载](#5-首次运行与模型下载)临时关闭离线模式，先完成一次下载。

**Q：首次提问很慢？**
A：首次需要加载 Embedding 模型和构建 LLM 客户端，通常需要数秒；后续问答会明显加快。

**Q：`.doc`** **文件解析失败？**
A：`.doc` 通过本机 Word COM 解析。请确认 Windows 已安装 Microsoft Word；否则用 Word 另存为 `.docx` 后重新上传。

**Q：扫描件 OCR 很慢 / 识别不准？**
A：OCR 在本地 CPU 运行，约 1\~3 秒/页，页数多时请耐心等待。可调低 `OCR_DPI` 提速，或调大 `OCR_MIN_TEXT_CHARS` 减少触发；手写体、模糊拍照和复杂表格的识别效果有限，必要时先转成清晰 PDF。若完全不需要扫描件识别，设置 `OCR_MIN_TEXT_CHARS=0`。

**Q：图片能像 PDF 一样预览版式吗？**
A：图片没有 PDF 版式预览，引用时展示 OCR 文本并支持下载原文件。

**Q：PDF 预览打不开 / 提示企业加密？**
A：图片没有 PDF 版式预览；DLP 加密文件或无法导出的文档会退回"网页版全文预览"；若仍无法生成，请使用"下载原文件"。

**Q：清空知识库时提示失败？**
A：通常是向量库目录被其它进程占用。关闭其它正在运行的实例后重试；数据清空逻辑已优先在 collection 层执行，一般无需手动删文件。

**Q：检索报** **`ef or M is too small`** **之类的错误？**
A：这是 hnswlib 索引异常，代码已内置两级兜底（普通相似度检索 → 全量余弦检索），通常可自动恢复。若持续出现，可清空知识库后重新入库。

**Q：回答没有引用来源？**
A：正常回答会带 `【来源：文件名】`；若明确回复"暂未检索到相关资料"，则不会标注来源，这是预期行为。

**Q：能否接入其它大模型？**
A：可以。只要提供 OpenAI 兼容接口，修改 `OPENAI_BASE_URL` 与 `MODEL_NAME` 即可，无需改代码。

## 约束与边界

- 仅注册 1 个工具（知识库检索），无联网、无代码执行、无外部 API 调用（LLM 除外）。
- 不做权限体系、用户体系、审计日志；仅通过单一管理口令区分管理/普通用户。
- OCR 面向印刷体与清晰截图：手写体、低分辨率扫描、复杂多栏/表格版式的识别效果有限，表格会退化为文本行。
- 扫描件 OCR 为 CPU 计算，速度约 1\~3 秒/页，大文件入库会明显变慢。
- Excel 只做文本行级入库，不保留公式计算结果以外的结构信息。
- 不接 MES / OA / 工单等业务系统。
- 回答仅作辅助参考，最终以正式文件与责任人判断为准。

## 安全须知

- `.env` 中包含 API 密钥与管理口令，不要提交到 Git，也不要随安装包分发。
- 管理口令建议使用强口令，并定期更换（更换后已登录令牌自动失效）。
- 上传文件仅按文件名落盘到 `data/docs/`，已做路径穿越防护。
- 如需对外网开放，请在反向代理层增加 HTTPS、访问控制与限流。
